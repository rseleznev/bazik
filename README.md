# Bazik

Балансировщик нагрузки L4.
На текущий момент:

1. Только TCP-балансировка
2. Только режим zero-copy с риском потери информации при ошибках
3. Только один алгоритм балансировки - случайный выбор сервера
4. Логи только в stdout

### Режим проксирования (proxy_mode)

Параметр отвечает за то, каким образом происходит передача пакетов из клиентского сокета в серверный и обратно.

#### zero-copy

В этом режиме данные не копируются в пользовательское пространство, а переносятся из одного сокета в другой через pipe.
При ошибке данные, которые были скопированы (и удалены) из сокета, будут потеряны. В зависимости от параметра retry_amount, либо оба соединения будут закрыты (если retry_amount=0), либо будет попытка найти новый сервер (если ошибка сервера и retry_amount>0)

### Количество ретраев (retry_amount)

Управляет поведением при серверной ошибке

Если необходима целостность данных, следует установить 0, в таком случае при первой же ошибке соединение с клиентом будет закрыто и клиент должен будет начать передачу заново

Если RetryAmount >= 1, может нарушиться целостность, т.к. клиент не узнает об ошибке и передача другому серверу продолжится со следующего полученного сообщения клиента с потерей полученных ранее и не доставленных данных
